# Aethelgard Atlas — план развития

Статус: ранний прототип. Цель — браузерный редактор политической географии мира Aethelgard (2147), с современной GIS-подачей и альтернативной географией Европы.

> Важно: исходные полигоны — схематические заглушки. Не считать их точной географией или подтверждённым каноном. Новые названия и границы по умолчанию должны оставаться предложениями до авторского утверждения.

## Этап 1 — надёжная основа (приоритет P0)
- [ ] Перенести приложение в удобную структуру проекта и описать запуск в README.
- [ ] Проверить работу в Chrome, Firefox и мобильном браузере.
- [ ] Улучшить сохранение: autosave-индикатор, восстановление после перезагрузки, резервная копия.
- [ ] Добавить отмену/повтор действий (undo/redo), подтверждение удаления и защиту от случайного сброса.
- [ ] Валидация импортируемого JSON и версия схемы проекта.
- [ ] Убрать небезопасное отображение пользовательских данных через HTML-шаблоны; использовать безопасное создание DOM-узлов.

## Этап 2 — удобное редактирование карты (P1)
- [ ] Перетаскивание вершин существующих границ.
- [ ] Вставка и удаление вершин, закрытие полигона и привязка к соседней границе.
- [ ] Выбор объектов мышью, панорамирование, масштабирование и кнопка «вписать карту».
- [ ] Добавление, перемещение, переименование и удаление городов.
- [ ] Слои: государства, провинции, города, транспорт, рельеф, спорные территории.
- [ ] Поиск объектов, фильтры по типу и статусу канона.
- [ ] Проверки топологии: самопересечения, дырки, случайные разрывы и наложения границ.

## Этап 3 — настоящая географическая основа (P1)
- [ ] Подключить лицензированный/открытый набор геоданных Европы (например, Natural Earth) с указанием лицензии и источника.
- [ ] Заменить условный фон на реальную базовую геометрию, затем редактировать её для сеттинга 2147.
- [ ] Выбрать проекцию, масштаб и координатную систему; не выдавать схему за географически точную карту.
- [ ] Создать редактируемые слои рельефа: хребты, плато, долины, реки, побережья и изменённые водоёмы.
- [ ] Хранить базовую географию отдельно от политических границ, чтобы изменения рельефа не ломали данные государств.

## Этап 4 — лор и канон (P1)
- [ ] У каждого объекта: стабильный ID, название и варианты, тип, столица, население (если известно), режим, отношения, заметки и ссылки на документы канона.
- [ ] Статусы «Канон / Предложение / Черновик» и история решений с датой и обоснованием.
- [ ] Подсветка противоречий с World Bible и CANON_STATUS.md.
- [ ] Словарь географических названий, языковые варианты и поиск по альтернативным названиям.
- [ ] Не считать автоматически созданные города, столицы и границы каноном без подтверждения автора.

## Этап 5 — экспорт и совместная работа (P2)
- [ ] Экспорт карты в SVG/PNG и печатный лист с легендой, масштабом и датой версии.
- [ ] Импорт/экспорт GeoJSON и CSV; документированный формат проекта.
- [ ] История версий и сравнение двух редакций карты.
- [ ] GitHub workflow: сохранение утверждённых данных в репозитории и pull request для значимых изменений.
- [ ] Автоматические проверки JSON и геометрии в CI.

## Рекомендуемый порядок
1. Надёжность данных и UX (сохранение, undo/redo, безопасный импорт).
2. Редактирование вершин и управление городами.
3. Реальная географическая подложка и слои рельефа.
4. Привязка объектов к канону и история решений.
5. Экспорт, сравнение версий и интеграция с GitHub.

## Критерий первой полноценной версии
Пользователь может открыть карту, создать/изменить/переместить территорию и город, сохранить проект, закрыть вкладку, вернуться без потери данных, экспортировать GeoJSON/SVG и однозначно отличить утверждённый канон от черновых идей.
